## 本文

クラウドサービス、いくつ使っていますか。私は数えたら 10 を超えていました。Cloudflare、OpenAI、データベースのホスティング、深夜のテンションで契約した何か。それぞれに管理画面があり、それぞれに請求が来ます。「今月、合計でいくら使ったか」を知るには、全部にログインするしかありませんでした。

それが嫌で、TollCat という iOS アプリを作りました。各サービスの公式請求 API から今月の利用額を取ってきて、1 つの数字に足し上げるだけのアプリです。ロック画面のウィジェットにも同じ数字が出るので、ほとんどの日はアプリを開くことすらありません。無料で、MIT ライセンスで、ソースは全部 GitHub にあります。

この記事は宣伝ではなく(いや、少しは宣伝ですが)、80 を超える請求 API を 1 つのアプリに繋いでみて分かったことの記録です。

### 「今月」の定義が各社バラバラ

一番の想定外はここでした。「今月いくら使ったか」という単純な質問に、各社の API はまったく違う形で答えてきます。

- カレンダー月で締める会社
- 契約日起点のローリングウィンドウで締める会社
- 昨日までの利用量しか教えてくれない会社
- 【実例:具体的に苦しかった 1 社のエピソード】

アプリとしては「今月の合計」という 1 つの数字を出したいので、全部をカレンダー月に折り直す換算ルールを設計する必要がありました。【換算ルールの概要と、境界日で踏んだバグの実例】

### 同じ請求を二重に数える罠

複数のエンドポイントから取った数字を足すと、同じ課金が両方に含まれていることがあります。【実例:重複計上に気づいた経緯と直し方】。この種のバグの嫌なところは、数字が「それらしく」出てしまうことです。テストは実アカウントの請求書と突き合わせるしかありませんでした。

### 請求 API がそもそも無い会社

対応リストを広げていくと、請求 API を提供していないサービスに突き当たります。ここは諦めて「検針ポスト」という仕組みにしました。請求メールをアプリ専用のアドレスに転送すると、金額だけが取り出されて他のサービスと同じように合算される、というものです。メールの本文はパースしたら捨てます。

### 認証情報を端末から出さない、を構造で守る

このアプリの前提は「ユーザーが API キーを貼り付けてくれること」なので、キーの扱いは設計の中心でした。

- キーは端末の Keychain にだけ保存。iCloud にもバックアップにも入りません
- 請求の取得は端末から各社 API へ直接。間にサーバーはありません
- モジュール構成で保証:ウィジェットはネットワークモジュールをリンクしない(ウィジェットが勝手に通信できない)、請求モジュールとチップ(投げ銭)モジュールは互いにリンクしない(キーが課金経路に流れ得ない)

「気をつける」ではなくリンク関係で禁止する、というのが個人開発でも一番効く安全策でした。人間は気をつけられないからです。

### App Store 配布と「本当にこのソースから作られたのか」問題

オープンソースの請求アプリと言っても、App Store のバイナリは Apple が再署名・暗号化するため、ソースからバイト一致で再現することはできません。できる範囲の保証として、公開 CI がタグからビルドして署名付きの来歴を残し、Mach-O の UUID で手元のアプリとそのビルドを突き合わせられるようにしました。この方式の限界も含めて、手順はリポジトリの VERIFY.md に書いてあります。

### まとめ

- 「今月いくら」という単純な質問ほど、実装は単純ではありませんでした
- 請求データの正しさは、実請求書との突き合わせでしか担保できませんでした
- 安全は運用ではなく構造で守る。モジュールのリンク禁止は個人開発でも安い保険です

TollCat は App Store で無料公開しています(iOS 26 以上、iPhone / iPad)。対応サービス一覧は https://tollcat.app/providers/ に、ソースは https://github.com/KUD-00/tollcat にあります。対応してほしいサービスがあれば issue でどうぞ。猫の手も借りたいので、PR はもっと歓迎です。
